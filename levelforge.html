LevelForge

An offline-first, gamified habit tracker for Android. Every habit you complete earns XP, streaks pay bonuses, and milestones unlock badges on the climb from Beginner to Habit God.

01

The problem

Most habit trackers are checklists. They work for a week, then the novelty wears off and the streak quietly dies. LevelForge started as a web app (Flask + React) that borrowed mechanics from games — XP, ranks, badges — to make consistency feel rewarding. But habits live on your phone, and opening a browser tab to tick off “Drink water” is exactly the kind of friction that kills a habit.

goalRebuild LevelForge as a native mobile app where checking in takes one tap, feels rewarding, and works anywhere — even with no signal.

02

Constraints

  • Keep everything users liked about the web version: the 10-rank ladder, the original badge artwork, the dark neon look.
  • Work fully offline; the existing server should be optional, not required.
  • Distribute outside the Play Store at first — so the app has to earn trust on its own (signing, permissions, transparency).
03

Key decisions

01

Offline-first, with the server as an optional extra

Habits, XP, streaks, badges, analytics, reminders and the AI coach all run on the device (Zustand persisted to local storage). The existing Flask/Supabase backend powers only what genuinely needs a server: leaderboards, friends, chat and server-side AI replies.

Why: the core loop — check in, earn XP — must never wait on a network or a sleeping free-tier server. This decision paid off later, when the cloud database went down and the app kept working.

02

A derived game engine instead of a running total

Rather than adding and subtracting XP as users tap, a pure TypeScript engine recalculates everything from the check-in history: streaks, XP, level, rank and badge progress.

  • Un-checking a habit removes exactly the XP it gave — no drift, no exploits.
  • Editing a habit's schedule or archiving it never rewrites past days (each habit keeps a schedule history and pause ranges).
  • The rules are testable in isolation: 30 unit tests cover streaks, rest days, schedule edits, weekly goals and badge unlocks.
03

Rebalancing the economy

The rules: +10 XP per quest, streak bonuses of +5 / +15 / +25 at 3 / 7 / 30 days, +50 for a Perfect Day, and badge rewards.

Early testing exposed a problem: badge rewards inherited from the web app (up to 5,000 XP) let a new user with nine starter habits jump two ranks on day one — making ranks meaningless. I tied badge rewards to rarity (25 → 800 XP), recalibrated three “secret” badges that were trivially easy, and added a balance test that fails if badge XP ever outweighs habit XP on day one.

04

What I built

  • Dashboard — rank, level and XP bar, streak flame, daily progress ring, and Today's Quests with a one-tap check-off, floating “+XP”, particle burst and haptics.
  • Habits — a 4-step creator (daily, specific weekdays, or “3× per week”), time windows and reminders, archive/restore, calendar history, CSV import/export.
  • Analytics — a GitHub-style 52-week heatmap, this-week-vs-last comparison, monthly trend, best time of day, category split, streak health.
  • 78 badges across 14 categories with original artwork and six rarity tiers — including secret, recovery and time-of-day badges.
  • Celebrations — LEVEL UP!, rank-up, badge-unlock and Perfect Day moments with confetti and haptics.
  • AI coach — plans the day, detects burnout, builds streak-recovery plans; runs on-device and upgrades to the server AI when connected.
  • Arena — leagues, global and friends leaderboards, real-time chat (Socket.IO) via the optional cloud.
  • Onboarding & landing page — animated splash, a 4-step “create your hero” tour, and a website with download, checksums and a dev blog.
05

Design system

A “cyber dark-glass” theme: obsidian backgrounds, frosted cards with neon borders, electric purple for progress, gold for XP, fire orange for streaks. Built as a reusable UI kit (cards, buttons, progress rings, sheets, badge art) with dark and light themes, and accessibility labels on every interactive element. The original ~190 MB of badge and rank artwork was converted to WebP at ~3 MB with no visible quality loss.

06

Shipping outside the Play Store

Sideloaded apps are judged harshly by users and by Google Play Protect, so release engineering was a feature in itself:

  • Signed with a dedicated release key; its fingerprint is published so every update can be verified.
  • Permissions cut from 25 to 7. Libraries had silently added camera, storage and 18 phone-maker “badge” permissions the app never uses — all stripped. What remains: notifications, vibration, network, and restoring reminders after a reboot.
  • Targets the latest Android (API 36), ARM-only build to halve the download size.
  • Verifiable downloads: a release script reads version, size, minimum Android version and checksums from the APK itself and publishes them on the site.
  • Hardened the client: the server address is locked in release builds — an editable URL would let someone trick users into sending their password to a fake server.
07

The hardest bugs — and how real devices solved them

Two bugs appeared only on a real phone (OPPO, Android 12, ColorOS). My first two fixes were educated guesses tested in a browser — and both missed. Connecting the phone over USB and reading its logs found the real causes within minutes.

bug 01

The app closed after “Continue” during onboarding.

The crash log read:

[Worklets] Tried to synchronously call a Remote Function … at QuestsStep

An animation running on Android's UI thread called an ordinary JavaScript helper — fatal on a phone, invisible in a browser (which runs animations on the JS thread).

Fix: compute the values before the animation; audit every animation in the app for the same pattern.

bug 02

Scrolling past the end wrapped to the opposite end.

Logging scroll positions on the device showed it precisely: at the bottom (y = 1635), one more flick produced momentum 1635 → 0 in a quarter of a second. React Native starts Android flings with an unbounded limit and cancels them at the edge; ColorOS's custom “bounce” turns that cancellation into a jump to the wrong end.

Fix: a reusable scroll guard that cancels momentum after a flick that started pinned to an edge. Verified on the device: 24 bogus flings blocked, normal scrolling unaffected.

bug 03

The cloud went dark.

The backend reported:

tenant/user … not found

Checking DNS, configuration and history showed the Supabase project had been auto-paused after inactivity — not a code bug. After restoring it, I verified the login and sign-up paths against the live server using requests designed to change nothing in the database.

09

What I learned

Real devices beat assumptions.

The browser said everything worked; the phone disagreed. Logs and measurements ended two days of guessing in minutes.

Derive, don't mutate.

Computing game state from history made the app correct by construction and easy to test.

Game balance is a product decision.

One mis-tuned number (a badge reward) quietly broke the meaning of the whole rank system.

Trust is engineered.

For an app outside the Play Store, signing, minimal permissions and published checksums matter as much as features.

Free tiers have failure modes.

Inactive free databases pause — monitoring and backups belong in the plan, not the post-mortem.
